## 2. Annotation: RefSeq kept, and a general normalizer built

Ensembl was evaluated first, as instructed, and rejected on measurement: it uses `gene_biotype`
exactly like RefSeq (`gene_type` appears **zero** times in Ensembl 116's yeast and zebrafish GTFs),
so it does not solve the attribute-key problem, and its primate assemblies are gorGor4 (2014),
Pan_tro_3.0 (2016) and Mmul_10 (2019) against the RefSeq T2T builds already on disk.

**`scripts/normalize_annotation.py`** handles four conventions (GENCODE, RefSeq, Ensembl, FlyBase),
auto-detects which is in use, maps the source vocabulary onto GENCODE's, re-types mitochondrial
rRNA/tRNA by contig (RefSeq has no `Mt_*` classes at all), and **errors on any unmapped term rather
than passing it through**. Full rationale in `methods.md`.

Its gate, which must pass before it is pointed at a new species:

```
python3 scripts/normalize_annotation.py --selftest
```

reproduces the hand-built `data/ncrna_tx_human_v49.txt` (2,447) and `ncrna_tx_mouse_vM38.txt`
(2,579) and both `tx_to_gene_*.tsv` by **exact set equality**. Currently passing.

Four defects it had to absorb, each of which produced a plausible wrong answer rather than an error
(detail in methods.md): RefSeq's `transcript_id ""` on gene lines kills gffread; FlyBase transcripts
were being extracted twice; nine trans-spliced `mod(mdg4)` transcripts have strand `.` and kill
RiboCode; RefSeq C. elegans reuses two transcript IDs across loci.

## 3. Reference infrastructure

`sbatch --array=0-6 scripts/xspecies/build_species_refs.sbatch` builds, per species: normalized GTF
plus drop lists, transcriptome FASTA, STAR index, decoy-aware salmon index, RiboCode annotation.
Parameters come from `scripts/xspecies/species.tsv`, the single table also read by
`riboseq_align.sbatch`, so an annotation version cannot drift between them.

Array index: `0 yeast, 1 celegans, 2 fly, 3 zebrafish, 4 macaque, 5 chimp, 6 gorilla`.
Every step has an idempotent skip guard, so a re-run resumes.

Two parameters are per species and must not be copied from the mammalian defaults:
`--sjdbOverhang` (max RNA read length minus 1) and `--genomeSAindexNbases`
(`min(14, log2(genome_bp)/2 - 1)`, so **10 for yeast, 12 for worm and fly**). STAR does not error on
a wrong value, it just builds a bad index, so the registry reads both back out of
`genomeParameters.txt` rather than assuming them.

**Use the gpu partition.** `medium` was backed up on priority; `--partition=gpu` with no `--gres`
starts immediately and has ~900 idle CPUs.

Verify with:
```
python3 scripts/xspecies/build_reference_registry.py --check     # exits nonzero on any failure
python3 scripts/xspecies/build_reference_registry.py             # writes the registry
```
It checks that each STAR index recorded the intended parameters, that the ncRNA drop list is
non-empty, that the salmon index has decoys, that RiboCode kept most transcripts, and that every
transcriptome ID joins to tx2gene.

The reference tree was renamed `genomes/primates_t2t` -> **`genomes/xspecies_refs`** (it holds worm,
fish, fly and yeast too) and fly was added as symlinks to the canonical FlyBase copy.
**Never point `archive_to_warm.sh` at `xspecies_refs/fly`**: it resolves with `readlink -f` and
would archive and then delete the FlyBase originals.

## 4. Adapters are measured per run, never assumed

`bash scripts/xspecies/probe_adapters.sh [label ...]` -> `data/external/xspecies/adapter_probe.tsv`.

**This is not a formality.** The standing cluster rule names TruSeq `AGATCGGAAGAGC`, and every
Ribo-seq dataset this project had processed used it. The worm arm does not: GSE52905 is **83.2%
`TGGAATTCTCGGGTGCCAAGG`** (Illumina small-RNA) and **0.0% TruSeq**. Trimming it with the standing
default would have removed nothing, left ~20 nt of adapter on every 51 nt read, and then
`-m 20 -M 40` would have DISCARDED those reads for being too long, producing a near-empty BAM with
no error anywhere.

Two further details the probe encodes: it picks the **longest** panel member above threshold rather
than the highest-scoring one (a 13 nt prefix always out-scores the full 21 nt adapter, and cutadapt
wants the full sequence); and it decides `--trim-n` on N-padding alone, because the human arm is
99.7% N-padded but its read lengths run 35-51, so a fixed-length test misses it.

Results so far agree with `heldout_config.sh`'s independently-recorded `ADAPTER_MODE=trimn` for
`human_ruizorera`.

## 7. Open decision

**The macaque assembly has no mitochondrion.** `GCF_049350105.2` T2T-MMU8v2.0 ships 22 contigs
(chr1-20, X, Y) and no MT sequence. Every other species carries the expected 22 Mt_tRNA + 2 Mt_rRNA;
macaque has zero. Its 464 rRNA and 429 tRNA entries are all nuclear, so the ncRNA drop set is still
correct, and the normalizer's guard flagged it rather than letting it pass.

The consequence is for alignment, not annotation. With no chrM in the index, mitochondrial
footprints (a real and often large fraction of a Ribo-seq library) have nowhere correct to map, and
the likely destination is a NUMT, which a T2T assembly resolves in unusual completeness. That is
silent signal corruption on one of the four species in the iPSC-CM comparison, and it makes macaque
the only species whose mito reads are handled differently from the rest.

Not patched, because adding `NC_005943.1` to the FASTA and GTF modifies a reference shared across
projects. Options: (a) accept and document, quantifying the unmapped fraction after alignment;
(b) supplement the reference with the RefSeq macaque mitochondrion, restoring consistency with the
other six species.
