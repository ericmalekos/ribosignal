# arch_attn -- model architecture panels (attention + Mamba)

Schematic architecture figures for the two candidate models. Nothing here is data-derived except the
worked ORF-track example (below) -- these are structural diagrams, and every layer, kernel size, dilation,
normalisation, head and tensor shape is read literally off `scripts/model.py` + the run's `args.json`, so
the panels are reimplementable.

## Deliverables (the chosen style)

| file | model | mixer region |
|---|---|---|
| `arch_rinalmo.{pdf,png}` | `orf_v2_attn` (deployed) | `2 x Transformer Blocks`, 8 heads, pre-norm |
| `arch_rinalmo_mamba.{pdf,png}` | `orf_v2_mamba4` | `4 x Bi-Mamba Blocks`, d_state 16, d_conv 4, expand 2 |

The two panels are **identical except for the second dashed region**, so they can be placed side by side.
Both are 14.0 x 5.2 in.

**Visual grammar** (deliberately borrowed, both figures fetched and read rather than recalled):
- **Network** = RiNALMo Figure 1 (arXiv 2403.00043, fetched via arXiv HTML `x1.png`): narrow rectangles with
  90-degree rotated labels, a tinted model container with the name above it, each repeated stack inside a
  dashed sub-region labelled "*N x ...*" in italic, and residual connections drawn as arcs over the top into
  circled-plus junctions.
- **Inputs** = Orthrus Figure 1 panel B "Encode Transcripts" (bioRxiv 2024.10.10.617658, fetched via
  PMC11482885 `f0001.jpg`): literal black/white encoding matrices with nucleotide row labels, split into two
  chunks with an ellipsis, tracks stacked with `+` separators.

## Correctness notes

- The ORF-track rows are **computed by the production builder at render time**, not hand-drawn. An earlier
  revision drew them by hand as periodic 1-in-3 stripes with a single start and a single stop mark, which was
  wrong twice over: the occupancy channels are ORF-span occupancy (not periodicity), and drawing one start
  plus one stop implied a single ORF whose start and stop were not even in the same frame. The panel now
  renders the real values and the footnote states that the track encodes *every* candidate ORF.
- `start` is a **graded** channel, so it renders in greyscale (AUG black, CUG mid-grey, AAG faint); every other
  ORF-track row is binary. Coverage is continuous and so is drawn as a depth profile, not a matrix -- the one
  deliberate deviation from Orthrus, whose three tracks all happen to be binary.
- Occupancy opens at **AUG only** (`start_mask = atg`), which is why the CUG at position 7 gets a start weight
  but no span. Explained in `tutorial/source/model/architecture.md`.

## Superseded exploratory styles

Kept in the same folder and regenerated by the same script for reference; **not** the deliverable:

| file | what it was |
|---|---|
| `style1_panel`, `style2_flow`, `style3_tiers` | first pass: full figures (inputs + architecture + real held-out profile + eval bars) in BPNet / RiNALMo / Orthrus flavours |
| `arch_style1`, `arch_style2`, `arch_style3` | second pass: architecture-only panels in the same three flavours |
| `arch_style2h` | third pass: `arch_style2` rotated to landscape |

`style1_panel`/`style2_flow`/`style3_tiers` embed a **real** held-out prediction (ENST00000958170.1, 2,297 nt,
r = 0.911) read from `results/loto/orf_v2_attn_onehot_union_.../dropin/pred_profiles.npz` (`obs_flat` +
`pred_flat`); see `arch_attn_values.json`. Their eval bars were built when only the mamba4 cross-species matrix
had finished; the attn matrix has since completed 5/5 (attn mean CDS F1 0.971 vs mamba4 0.973), so those bars
would need regenerating if any of those three were ever revived.
